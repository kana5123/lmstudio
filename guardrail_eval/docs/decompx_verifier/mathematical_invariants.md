# 수치 불변식과 정밀도

## 불변식

DecompX 분해 `C[l,k]` 가 CLS 를 원천 토큰별로 가른 것이라면 아래가 성립해야 한다.

| # | 불변식 | 근거 |
|---|---|---|
| §8 | `sum_k C[l,k] == h_CLS[l]` | 분해의 정의 |
| §8 | 패딩 위치 기여 `== 0` | 마스크가 실제로 적용됐는가 |
| §12 | `sum_k D[l,k] == g_l` | §8 을 두 층에 적용한 차이. `D = C[l]-C[l-1]`, `g = h_CLS[l]-h_CLS[l-1]` |
| §15 | `sum_k p_lk == ||g_l||` | `p = g^T D / ||g||` 이므로 `sum_k p = g^T(sum_k D)/||g|| = ||g||` |
| §18 | `mass_pos - mass_neg == ||g_l||` | `sum relu(p) - sum relu(-p) = sum p` |

§12·§15·§18 은 §8 에서 대수적으로 따라 나온다.  독립된 세 개의 검사가 아니라
같은 성질의 세 가지 표현이다.  그래도 구현 실수를 잡기 위해 각각 따로 측정한다.

## 정밀도 — 두 단계 판정

**(1) 대수적 정확성은 float64 에서 판정한다.**  구현이 옳은지의 문제이기 때문이다.

같은 표본 12개, dtype 만 바꾼 단일 변수 비교:

| | L1–L10 복원 | L11 | L12 | D 보존 |
|---|---:|---:|---:|---:|
| float32 | 5.42e-06 | 2.73e-04 | 3.77e-04 | 3.71e-04 |
| **float64** | **1.10e-11** | **2.72e-10** | **3.74e-10** | **3.01e-10** |

약 10^6 배 차이다.  **분해는 대수적으로 정확하다.**  float32 초과분은
11층에서 CLS 크기가 12배(2.20 → 26.66) 뛰며 상쇄가 커져 생기는 반올림이다.

| 층 | 절대오차 | 상대오차 | CLS 노름 |
|---:|---:|---:|---:|
| 10 | 1.0e-05 | 4.7e-06 | 2.20 |
| 11 | 2.4e-03 | 9.3e-05 | 26.66 |
| 12 | 3.5e-03 | 1.5e-04 | 24.08 |

**(2) 추출은 float32 로 한다.**  float64 는 같은 길이에서 약 85배 느리다
(128–256 토큰에서 15.32 초 대 0.18 초).  전체 141,027 표본이 float32 11.3 시간
대 float64 약 950 시간이다.

float32 허용치를 넓힌 근거는 "그냥 통과시키려고" 가 아니라, **그 오차가 SDR 증거를
바꾸는지 직접 잰 결과**다.  같은 표본에서 float32 증거 대 float64 증거:

| 증거 | 코사인 최소 | 상대 L2 최대 |
|---|---:|---:|
| g | 1.000000 | 7.5e-06 |
| zD_pos / zD_neg | 1.000000 | 2.7e-05 / 4.8e-05 |
| zH_pos / zH_neg | 1.000000 | 3.1e-06 / 7.6e-06 |
| zE_pos / zE_neg | 1.000000 | 5.9e-06 / 9.3e-06 |
| mass_pos / mass_neg | — | 1.5e-05 / 1.6e-05 |

12층 복원 상대오차 7.4e-4 는 pooled 증거로 전파되지 않는다.
설정값은 `src/decompx_verifier/config.py` 에 명시했다.

## §16 low-motion 임계

`||g_l||` 가 작으면 전역 방향이 불안정하다.  계산은 이미 수치적으로 안전한 형태
`p = (g^T D)/(||g||+eps)` 를 쓴다.

임계값은 **추출 시점에 정하지 않는다.**  대신 `g_norm` 을 그대로 저장하고,
학습 분할이 확정된 뒤 **train 통계에서만** 임계를 정해 `low_motion` 플래그를 만든다.
test 결과를 보고 고르는 경로를 원천 차단하기 위해서다.
