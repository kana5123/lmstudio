# 데이터셋 출처 등록부 (dataset provenance registry)

목적: **동결된 PromptGuard2(`meta-llama/Llama-Prompt-Guard-2-86M`) 위에서 TP(참양성) 대 FP(거짓양성) 방향을 학습**하되, 그 방향이 *출처에 강건*하도록(source-robust) 데이터셋을 고르기 위한 근거 문서.

이 파일은 4명의 조사자 보고를 통합하고, 그중 핵심 주장 7건을 작성자가 로컬 파일에서 직접 재측정해 확인한 결과다. 기계 판독용 동일 내용은 `/home/kana5123/ETRI/guardrail_eval/data/multisource_guard/dataset_registry.json` 에 있다.

표기 규칙:
- **확인 못 한 것은 문자 그대로 `UNKNOWN`** 이라고 적는다. 그럴듯한 라이선스·학회·개수로 메우지 않는다.
- 개수 앞에 "재측정"이 붙으면 실제 파일을 열어 센 값, "주장치"가 붙으면 논문·카드가 말하는 값이다. 둘이 다르면 둘 다 적었다.

## 0. 왜 이 문서가 필요한가 — 한 줄 요약

프롬프트 가드 데이터셋 대부분은 **benign 절반과 attack 절반이 서로 다른 곳에서 왔다.** 한쪽은 사람이 쓴 지시문 코퍼스, 다른 쪽은 대회 제출물이나 GPT 합성물이다. 이 상태로 TP/FP 방향을 학습하면 모델이 배우는 것은 "공격이냐"가 아니라 **"어느 코퍼스에서 왔느냐"** 다. 실제로 이 프로젝트에서 이미 관측된 현상이기도 하다(메모리 항목 `jot_tpfp_corpus_confound`: PG2 오탐 100%가 wildchat 출처).

따라서 선택 기준은 성능 지표가 아니라 **같은 출처 안에 benign 과 attack 이 둘 다 있는가, 그리고 그 둘이 같은 텍스트에서 파생됐는가** 다. 아래 1절이 그 기준에 따른 판정이다.

## 1. 같은 source 안에 benign 과 attack 이 모두 있는가 — 선택 기준

이 절이 데이터셋 선택의 유일한 1차 기준이다. 등급은 세 단계로 나눈다.

- **1등급(사용 가능)**: 공격 텍스트가 *같은 benign 텍스트에서 파생*된 것이 파일 수준에서 확인됨. 주입 문장만 빼면 두 행이 같아지므로, 분류기가 코퍼스 문체가 아니라 주입 자체를 봐야만 구분할 수 있다.
- **2등급(조건부)**: 같은 팀/같은 수집 파이프라인에서 양쪽이 나왔지만 행 단위 짝은 없음. 길이·문체 교란을 통제해야 쓸 수 있다.
- **3등급(사용 금지)**: 두 컬렉션을 이어 붙인 것. 길이나 생성기 문체만으로 라벨이 거의 분리된다.

### 1-1. 라벨 정의 함정 — 유해함(harmful)은 jailbreak 이 아니다

이 등록부에서 가장 비용이 큰 함정이다. AI2 두 논문은 **유해성 축과 jailbreak 구조 축이 직교한다**고 명시한다.

- `vanilla_harmful` 50,050행 = 유해하지만 **공격 기법이 전혀 없는** 직접 요청.
- `adversarial_benign` 78,731행 = **완전한 jailbreak 표면형**을 갖되 유해 의도가 없음.

따라서 "유해 = 공격"으로 사상하면 (a) 기법 없는 직접 요청 5만 건을 jailbreak 으로 라벨하고 (b) jailbreak 형식 7.8만 건을 benign 으로 라벨해서, 이 데이터셋이 제공하려던 하드 네거티브 신호를 통째로 파괴한다. 공격 탐지기의 올바른 축은 **적대 축**(`data_type` 접두, `adversarial` 불리언)이고 유해 라벨은 두 번째 독립 필드로 남겨야 한다.

이 구분은 대상 모델 정의와도 맞는다. Prompt Guard 2 모델카드는 malicious 를 **"이전 지시를 명시적으로 무시하려 시도"**로 정의한다 — 유해성이 아니다. PG2 위에서 TP/FP 방향을 학습한다면 라벨 축도 여기에 맞춰야 한다.

### 1-2. 같은 파일 안에서 라벨 정의가 서로 모순되는 사례 (PIGuard)

PIGuard `train.json` 은 유해성 처리가 내부적으로 모순된다.

- `xtest-v2-copy` 450행 **전부를 benign(0)** 으로 라벨했는데, 작성자가 로컬 parquet 을 재측정한 결과 그중 **200행이 XSTest 자신이 UNSAFE 로 지정한 `contrast_*` 프롬프트**다.
- 반대로 `Prompt-Injection-Mixed-Techniques` 1,174행은 유해 콘텐츠 *요청*을 **attack(1)** 으로 라벨한다.

즉 같은 파일이 유해 요청을 한쪽에서는 benign, 다른 쪽에서는 attack 으로 학습한다. 이 파일을 라벨 그대로 쓰면 방향 벡터가 무엇을 가리키는지 정의되지 않는다.

### 1-3. 출처 간 오염 — 데이터셋들은 서로 독립이 아니다

- PIGuard 안에서 **1,019개 프롬프트가 2개 이상 `source` 에 등장**하고, **5개 프롬프트는 0 과 1 라벨을 동시에** 갖는다(대표적으로 표준 DAN 프롬프트).
- 원인 사슬: `verazuo/jailbreak_llms` → `jackhhao/jailbreak-classification` → `xTRam1/safe-guard` 씨앗 → ProtectAI 혼합에도 등재 → PIGuard 가 이 넷을 *각각 따로* 흡수. `GuardrailsAI/detect-jailbreak` 도 verazuo 가 근간(14,524행).
- PIGuard 는 `xTRam1`(8,236) · `deepset`(546) · `jackhhao`(1,044)의 **train 분할을 통째로** 가져왔다(개수 정확히 일치). 따라서 이 데이터셋들의 자체 test 분할로 평가하면 학습셋과 상류가 같은 오염 상태다.

## 3. 확인하지 못한 것 (UNKNOWN) 과 그 이유

확인 못 한 사실을 그럴듯한 값으로 메우지 않았다. 아래가 전부다.

### 3-1. 접근이 막혀서 확인 불가

| 대상 | 확인 못 한 것 | 이유 |
|---|---|---|
| `microsoft/TaskTracker` | 상류 행 수, PIGuard 가 쓴 split | 데이터가 Microsoft 접근신청 양식 뒤 Azure Blob 에 있음. `huggingface.co/datasets/microsoft/TaskTracker` 는 HTTP 401 이고 HF 검색 결과도 없음 |
| `Harelix/Prompt-Injection-Mixed-Techniques-2024` | 카드·라이선스·크기·스키마 전부 | HF 페이지가 HTTP 401, 검색에도 없음. PIGuard 가 쓴 이후 게이트/비공개 전환된 것으로 보임. 라이선스는 ProtectAI 모델카드 서술을 인용한 **2차 출처 뿐** |

### 3-2. 문서에 절차가 없어서 재현 불가

- PIGuard 의 **표집 절차 전부** — Alpaca 4,000/52,002, chatbot_instruction_prompts 16,000/258,042, open-instruct 12,000/142,622, ultrachat 3,000, no_robots 1,500/9,500, grok 4,000, hackaprompt 5,000/601,757. 논문이 어느 것에 대해서도 방법을 밝히지 않음.
- BIPIA 의 **558개 문맥 선정** — 다섯 태스크 디렉터리에서 어떻게 뽑았는지 논문에 없음.
- PromptShield **train split 의 출처별 행 수** — 배포 `train.json` 에 `source` 필드가 없어 복원 불가. (평가 split 만 출처를 보존한다.) 따라서 HackAPrompt 5,000 은 코드가 *요청한* 값이지 측정치가 아니다.
- PIGuard `LLM Augmented set` 의 생성 프롬프트 — 논문 부록 D.3 에 **그림(이미지)** 으로만 있어 전사 불가.

### 3-4. 라이선스 충돌 (재배포 시 실제 문제)

- PIGuard 는 **MIT** 로 배포하면서 **CC BY-NC 4.0**(Alpaca, no_robots, StruQ) 콘텐츠를 재배포한다. README 자신이 "라이선스 문제로 InjecGuard 에서 PIGuard 로 개명했다"고 적고 있다. 사실만 기록하고 판단하지 않는다.
- PromptShield 는 **apache-2.0** 위에 Alpaca(`cc-by-nc-4.0`, 비상업)와 dolly(`cc-by-sa-3.0`, 동일조건변경허락)를 얹었고 저자들이 이를 조정하지 않았다.
- PIGuard `datasets/wildguard.json` 은 ODC-BY 게이트 데이터를 재배포하면서 별도 라이선스 표기가 없다 → `UNKNOWN`.

## 5. 이 등록부에서 곧바로 나오는 실행 지침

1. **1차 후보는 `allenai/wildjailbreak` 하나다.** 100% 짝 구조가 파일에서 확인되는 유일한 대규모 셋이고, `adversarial_benign` 78,731행이 곧 FP 쪽 하드 네거티브다. 단 라벨 축은 유해성이 아니라 `data_type` 접두(적대 축)로 잡을 것.
2. **길이 통제는 선택이 아니라 필수다.** 적대 프롬프트가 6~12배 길다. 길이 통제 대조군 없는 정확도는 무의미하다(메모리 `jot_tpfp_corpus_confound` 의 어휘 대조군 요구와 같은 성격).
3. **PIGuard `train.json` 은 라벨 그대로 쓰지 말 것.** XSTest 200행 오라벨, 라벨 충돌 5건, 교차 오염 1,019건, 중복 3,107행이 있다. 쓰려면 `source` 별로 잘라서 BIPIA(419쌍)·TaskTracker(재짝지음)만 취할 것.
4. **PromptShield 은 평가용으로만, 그것도 GitHub camera-ready 사본으로.** HF 판은 `source`/`type` 을 버려서 출처 분석이 불가능하다. 짝이 필요하면 dolly 부분 896쌍을 직접 재구성하거나, `StruQ.py` 로 benign 과 공격을 **같은 seed** 에서 다시 생성하는 편이 깨끗하다.
5. **평가셋 오염 확인 필수.** PIGuard 는 `xTRam1`/`deepset`/`jackhhao` 의 train 분할을 통째로 흡수했고, `valid.json` 에 WildGuard 24행이 들어 있어 그 24행은 모델 선택 오염이다. WildJailbreak 과 WildGuardMix 는 PIGuard 학습에 **전혀 쓰이지 않아**(22개 source 전수 확인) 외부 평가셋으로 깨끗하다 — 단 `wildguard.json` 971행만은 PIGuard 가 이미 점수를 내고 있는 부분이라 제외할 것.
